# B案「手元から、全国へ」実装設計

検索結果で「川や道路のライブカメラを地図から見るアプリ」と伝える。左に短い言葉、右に大きな実画面の端末1台。案名は画像に載せない。5244×2950pxの共通原稿1枚を中央クロップする。画像制作は本書の対象外。

参照：`DESIGN_HEADER.md`、添付 `ref_screenshot_02.png`。指定の `ref_screenshot_design.md` はローカルに見当たらないため、既存ストアの `../DESIGN.md` と実装を参照した。氷青、紺、青の強調、Noto Sans JP、既存iPhone枠を継承する。

## 配置と描画

座標は原稿左上基準の **(x, y, 幅, 高さ)**。文字枠は行ボックス、端末枠は回転前。重なり順は背景→光→等高線→影→端末→文字。

| 要素 | 配置・指定 |
|---|---|
| 背景 | `(0, 0, 5244, 2950)`。左上から右下への線形グラデーション：0% `#F3FAFD`、55% `#E5F3F7`、100% `#C7E3EC`。不透明 |
| 白い光 | `(200, 0, 3600, 2950)`。中心 `(2000, 1475)`、半径 `(1800, 1475)` の楕円放射グラデーション。中心 `#FFFFFF`・不透明度0.65→外端0 |
| 等高線 | 描画領域 `(2760, 0, 2484, 2950)` でクリップ。中心 `(3680, 1580)`、回転−12度の同心楕円8本。番号i=0〜7で横半径 `650+180i`、縦半径 `900+180i`。塗りなし、線幅5px、`#B6D6E5`・不透明度0.55。領域左端から240pxで不透明度0→指定値にフェード。地形を思わせる装飾であり、実地形・警戒範囲の表示ではない |
| 端末 | **`(3040, 456, 1000, 2037.18)`**、中心基準で時計回り **＋3度**。既存 `../public/mockup.png` と `Phone` の画面開口位置を使う（比率1022:2082）。画面と枠を一体で回転。遠近変形なし、不透明度100% |
| 端末の影 | 端末内側に収めた角丸シルエットから2層。長い影：オフセット `(0, 65)`、ぼかし100px、`#42627A`・0.20。短い影：`(0, 12)`、ぼかし24px、同色・0.18。透明画像の矩形全体に影を付けない |
| 見出し1行目 | **「川も道路も、」**、`(1000, 1040, 1600, 288)`、Noto Sans JP **900／240px**、`#102E49` |
| 見出し2行目 | **「地図で見る。」**、`(1000, 1328, 1600, 288)`、同じ書体・サイズ。「地図」だけ `#1E6FD9`、残り `#102E49` |
| 補助語 | **「ライブカメラ」**のみ、`(1000, 1696, 1600, 272)`、Noto Sans JP **700／226px**、`#42627A`。帯・チップ・アイコンは付けない |

見出しは句読点込み12文字、各行6文字。左揃え、字間0、カーニングなし。行高288px（1.2）、行ボックス間の追加余白0、2行目の下端から補助語まで80px。補助語の行高272px。自動改行・文字の横圧縮はしない。使用ウェイトは既存400/500/700/900の範囲内とし、本原稿の追加文字は700/900だけで構成する。

## 実画面の扱い

- 既存2枚目の**地図画面**を使う。川・道路と複数のカメラピンが見え、1地点を選択したプレビューも見える実キャプチャを採用する。詳細画面へ遷移せず、プレビューの上にも地図を十分残す。
- **添付画像にはピンは見えるが、選択地点のプレビューは出ていない。** 実装時は元の地図キャプチャ素材を確認し、なければ同じアプリの地図上で実際にピンを選択して撮り直す。プレビューの捏造や別画面からの貼り合わせで補わない。これは制作に必要な素材条件であり、添付だけで満たせた扱いにしない。
- 既存の元画面＋モックアップから組む。文字・背景・傾き込みのストア完成画像をそのまま端末素材として拡大しない。
- 通常時の穏やかな河川または道路のプレビューを選ぶ。ピンの位置・色・個数、地名、画像、時刻などを加工しない。プレビューの画像面が端末幅の概ね半分以上ある実UI状態を選び、縮小しても写真と地図の違いが分かるようにする。
- 地図の「地理院タイル」等の出典、プレビューの出典を残す。画面全体を等倍率で開口に収め、ベゼル・角丸・プレビューが出典を隠していないか確認する。既存 `Phone` は `object-fit: cover` のため、元画像の比率が合わず欠ける場合は本原稿側で `contain` にする。UIの一部分だけ拡大・移動しない。

## クロップと390px表示

中央基準、引き伸ばしなし。重要要素は保守的な共通枠 **`(630, 384, 3984, 2182)`** に収める。上下各13%・左右各12%を同時に削る場合もこの枠が残る。影と背景線は切れてよい。

| 表示 | 原稿上の切り抜き枠 | 端末と文字の残り方 |
|---|---|---|
| 21:9 | `(0, 351.29, 5244, 2247.43)` | 上下の余白が減り、左の文字と右の端末全体が横並びになる。端末の出典も残る |
| 3:2 | `(409.5, 0, 4425, 2950)` | 左右の装飾と余白が減る。約204万px²の端末面が、3行分の文字領域より大きく、唯一の写真・地図として主役になる。文字を巨大化したり別の絵を追加したりしない |

回転後の端末外接枠は約 **`(2987.38, 431.23, 1105.25, 2086.73)`**。下端2517.96pxを含めて共通枠内に収まり、上下を切らない。文字も全行共通枠内。元のB案より端末幅を850→1000pxへ増やし、見出しを340→240pxへ抑える。

**検索結果3:2は390×260px**、縮小率 `390/4425 ≒ 0.08814`。見出しは**約21.2px**、補助語は**約19.9px**となり、「川も道路も、」「地図で見る。」「ライブカメラ」が読める設計。各行は約120〜127px幅。端末の回転後外接枠は約97×184px、カード内の位置は約 `(227, 38)`。川・道路の線、ピン、写真プレビューの存在で使い方を補う。

端末内の地名・ボタン名・時刻・出典の細字を390pxで読ませる設計ではない。用途の理解は外側の3行で完結させる。出典は原画に完全に残し、縮小時の可読性と混同しない。

21:9を幅390pxにした場合は約390×167px、見出し約17.8px、補助語約16.8px、端末外接枠約82×155px。3:2より小さくなるが、短い文言と端末全体の対応は維持する。同じ1枚からのクロップなので、表示ごとの再配置はしない。

## 実装時の確認・避けること

- 原寸、中央21:9、中央3:2、上下13%＋左右12%の同時カットで文字・端末・出典の欠けを確認する。390pxでは3行が読め、端末が地図と分かり、ピンと写真プレビューが区別できることを確認する。満たせなければ実キャプチャの地図表示範囲・選択地点を調整する。
- 本書は座標と縮小率を計算した設計。画像の生成・書き出し・目視検証は未実施。制作時はフォント読込後に5244×2950px・sRGB・不透明PNGで出力する。
- 価格、「無料」、割引、URL、©、受賞、他ストアのロゴ、Appleバッジを追加しない。必要な出典表記は消さない。
- 日本地図の光点、機能一覧、台数の強調、追加コピー、REC表示、矢印、別置きのカメラ写真を足さない。文字に影・縁取りを付けない。
- 架空の警報、被災映像、安全保証、常時動画であるとの誤認を誘う表現を使わない。4+相当の穏やかな実画面にする。
