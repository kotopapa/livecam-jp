## 7. 言語別の総評

### やさしい日本語（app_ja_Hira.arb）

全体としては語彙の平易化は丁寧に行われており、防災用語には（かっこ）併記がほぼ徹底されている点は良好です。一方で最大の構造的問題は**表記スタイルが2系統に割れている**ことで、settings / detail / list / favorites / bosai 系は「全ひらがな＋原語を括弧に」、map_screen 系と後半の tip / hazard / facility 系は「漢字＋ふりがな」で書かれており、同一の遷移内で `ちず` と `地図（ちず）`、`ちかく` と `近（ちか）く`、`じしん` と `地震（じしん）` が混在します。次いで深刻なのが**同一語の訳ゆれ**で、「震度」が4通り、「出典」が5通り、「警戒」が3通り、「もう一度」が4通りに散っており、防災用語で1語1訳が崩れているのは実害に直結します。第三に、**行政区分の縮約**（市区町村→「市・町」、都道府県→「県」、自治体→「市や町」）が15キー以上で発生しており、区・村・都・道・府に住むユーザーが自分を対象外と誤読する恐れがあります。分かち書きは概ね妥当ですが、`{count}か しょ`（箇所の語中分割）、`ひじょうよう ひんの そうこ`、`アプリない かきん` のように語中で切れて別の意味に読めるものが数件あります。文長は SPEC 由来の長文（disclaimerText、mapShelterNoticeBody、mapFacilityNoticeBody）で1文90〜110文字が残っており分割が必要です。レイアウト面では ChoiceChip / Tab / バッジ用途のキー（rankingModeNow、shelterHazardInlandFlood、intensity5Lower、mapQuakeUnknownPlace）で訳が原文の3〜5倍になっており、実機での崩れが予想されます。

### 英語（app_en.arb）

全503キーのうち、気象庁多言語辞書に準拠した警報・注意報・震度・都道府県名などの公式対訳（約150キー）は品質が高く、ADAPT合成語も概ね妥当で、致命的な防災用語の誤訳は見当たりませんでした。指摘の中心は、辞書対象外のアプリ独自文言に残る「情報の脱落」（地震・津波タブから津波が消える、カメラ台数の単位が消える、代表点/おおよその区別が消える等）と、複数キー間の用語・綴り・大文字小文字の不統一です。特に綴り体系が英国式（colour / licences）と米国式（Favorites / color）で混在しており、リリース前にどちらかへ統一する必要があります。件数プレースホルダにICUの複数形分岐が使われていないため、1件のときに "1 cameras" と表示される箇所が広範に存在する点も要対応です。また、ARBではなく呼び出し側のDartコードで全角スペース「　」や全角括弧「【】」を英語文字列に連結している箇所が3件あり、英語UIに日本語の約物がそのまま出ます。ボタン系は概ね良好ですが、一部が名詞句のまま（Nearby live cameras / See the route）で、チップ・凡例には30〜40字の明らかな溢れ候補が残っています。

### 中国語簡体字（app_zh.arb）

全体としては機械翻訳をそのまま流したレベルではなく、「登録→添加」「共有→分享」「モバイル通信量→移动数据流量」など和製漢語の罠をきちんと回避できている良質な訳文である。繁体字の混入はゼロ、台湾用語（網路・影片・軟體・預設等）の混入も無く、簡体字ロケールとしての基本品質は保たれている。

一方で、**アプリ名だけが英語のまま残っている**点、**「海外」「涩谷」のように日本側の視点をそのまま持ち込んで中国語話者に誤解や機能不全を生む箇所**、および**「発表」「更新」「一覧」「出典」といった日本語語彙の直訳が場所によって訳し分けられている不統一**が主要な課題である。特に「更新（＝refresh）」をボタン文言で「更新」としている点は、中国語では「アプリのアップデート」と読まれるため実害が大きい。

防災用語は気象庁多言語辞書に忠実で、原則的に問題は無い。ただし辞書由来の「土石流」は中国大陸では「泥石流」が標準語であり、辞書に無い ADAPT キー（riskLandTitle・hazardLandslideTitle 等）まで「土石流」を踏襲した結果、「土砂災害」＝「土石流」という意味の狭窄が起きている。また震度表記が「烈度5弱」（日本語の弱を残す）と「近5级」（辞書訳）に割れており、同一画面で表記が揺れる。

句読点は、日本語の中黒「・」を一律「、」に置換した箇所が多く、中国語の「、」は並列名詞専用というルールに反している。節の区切りは「，」、対等連結は「·」への置換を推奨する。

修正の優先順位は、①高重大度7件（意味不通・機能不全）→②用語統一（应用／来源／列表／刷新／降水量）→③句読点の一括置換、の順が効率的である。

### 中国語繁体字（app_zh_Hant.arb）

全 503 キーのうち致命的な問題は限定的で、防災用語（警報・注意報・震度・避難場所・ハザードマップ）は台湾中央気象署／内政部の慣例語（暴潮・淹水・災害潛勢地圖・中暑）にほぼ正しく対応しており、簡体字の混入も languageNameZhHans の自称表記を除いてゼロ、台湾語彙（網路・影片・軟體・快取・行動網路・當機・權杖）の選択も概ね適切です。一方で、**アプリ名とシェア文が英語のまま未翻訳**である点、**pref09 が「櫔木」という別字になっている**点、**mapSearchHint に日本語新字体（渋・沢・広）が残っている**点は、いずれもユーザーの目に直接触れるため最優先で修正すべきです。

次に問題が集中しているのは和製漢語の直輸入で、特に「実況→實況」は中国語では「ライブ配信」を意味し、本アプリがライブ配信機能を持つため誤解の危険が高いです。「時点→時點」「一覧→一覽」「想定→預想」「対応→對應」「確認→確認」も中国語では別義または非文になります。また bosaiMuniNone / bosaiAdvisoryRegions / settingsNotifyLevelNote の 3 件は主語や述語が落ちて中国語として成立しておらず、いずれも警報表示という重要な文脈にあります。

用語一貫性では、「震源」が全て「地震位置」に置き換えられて専門語が失われている点（**本項は監査中に修正済み**）、「波浪」が「海浪／浪高」で揺れている点、「周邊／附近」の混在、中黒「・」の多用（26 キー）、全角「＝」と半角「 = 」の混在が目立ちます。JMA 多言語辞書由来のキーは原則そのままで問題ありませんが、advisory26（着雪→積雪）と heatAlert*（警戒→警報）は日本語原語と意味がずれているため、辞書側の再確認を推奨します。

### 韓国語（app_ko.arb）

全503キーを通読した結果、文体は「합니다체＋〜해 주십시오」で完全に統一されており、해요체や名詞形との混在、「할수있습니다」式の分かち書き崩れは1件も検出されなかった。この点の品質は高い。一方で問題が集中しているのは防災専門用語の系列内不統一と、日本語漢語・日本語組版の直輸入の2点である。とりわけ「高潮」がアプリ内で「고조／고위／폭풍 해일」の3通りに割れており、うち「고조」「고위」は韓国語話者に気象用語として通じないため、特別警報の設定画面とハザードレイヤーで意味が伝わらない恐れがある（気象庁辞書由来キーも系列内で割れているので、辞書の実データとの突き合わせを推奨する）。次に、「取得」を「촬영（撮影）」と訳した3キーは、SPEC が必須要件とする「取得時刻の明示」を「撮影時刻」にすり替えており、災害時の判断材料として誤認を招くため最優先で修正すべきである。組版面では鉤括弧「」が4キー、中黒「・」の箇条書きが2キー、全角「＋」が1キーに残存している。ADAPT キーは全体に丁寧に作られているが、riskLevelWatch（留意→추후 정보에 유의）と heatAlert*（原文にない「경보」の付加・分かち書きの不統一）はレイアウトと用語一貫性の両面で見直しが必要である。ボタン・チップ・タブの文字幅は概ね原文と同等かわずかに長い程度で、致命的な溢れは detailNotUpdating（Chip）と detailOpenOriginalPage（FilledButton）程度にとどまる。

### ベトナム語（app_vi.arb）

声調記号（dấu thanh・dấu phụ）の欠落や誤りは全503キーで1件も検出されず、この観点の品質は非常に高い。全角記号の混入も箇条書きの中黒「・」2キーのみで、句読点はおおむね現地化されている。一方で、**ハザードマップ系の「想定」を `dự báo`（予報）と訳した3キーは、仮定シナリオを実際の予報と誤認させる危険な誤訳**であり、避難判断に直結するため最優先の修正対象である。次いで「気象庁」を `Cơ quan Khí tượng` とだけ訳している7キーは、在日ベトナム人利用者にとって出典国が特定できず、SPEC C5 の出典表記要件も実質的に満たしていない。用語面では「災害」が `thảm họa` / `thiên tai` / `tai họa` の3通り、「洪水」が `lũ lụt` / `ngập lụt` の2通りに割れており、防災用語の一貫性に改善余地がある。最後に、ベトナム語は日本語の2〜4倍の字数になるため、Tab・ChoiceChip・_InfoChip・44pxバッジといった固定幅ウィジェットで確実にレイアウトが破綻する箇所が10件以上あり、UI用の短縮訳を別途用意すべきである。
