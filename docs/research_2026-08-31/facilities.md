# 防災拠点データ（給水拠点・防災備蓄倉庫・消防水利）調査記録

調査日: 2026-08-31 / 実装: `tools/facilities.py`, `.github/workflows/facilities.yml`

## 1. 結論（先に読む）

- **国による全国集約は存在しない**。避難場所（国土地理院 hinanmap）のような「1本のCSVを落とせば全国が揃う」データソースは、
  給水拠点・防災備蓄倉庫・消防水利・災害時給水栓のいずれにも無い。
- デジタル庁の**「自治体標準オープンデータセット」に様式（`消防水利施設一覧` など）はあるが、データ本体の全国集約は無い**。
  様式が決まっているおかげで**列名がほぼ統一されている**ので、集めさえすれば正規化は容易。
- したがって現実解は **CKAN横断検索**。最大の受け皿が **BODIK ODCS (`data.bodik.jp`)**（388組織・18,392データセット、CKAN API 認証不要）で、
  東京都は独自CKAN (`catalog.data.metro.tokyo.lg.jp`) を持つ。
- 実装した `tools/facilities.py` は CKAN の `package_search` を `title:` フィールド検索で叩き、
  タイトルで種別を判定 → ライセンスを判定 → CSVを取得 → 正規化 → `data/facilities/<JIS2桁>.json` に県別出力する。
- **量は消防水利に極端に偏る**（採用データセットの9割）。給水拠点は数十件、備蓄倉庫はほぼ皆無。
  これはデジタル庁標準様式に「消防水利施設一覧」があり「給水拠点一覧」「備蓄倉庫一覧」が無いことの直接の帰結。

## 2. どのCKANに何があるか

### 2.1 採用したポータル

| ポータル | ベースURL | robots.txt | API | 備考 |
|---|---|---|---|---|
| BODIK ODCS | `https://data.bodik.jp` | `/api/` 許可・`Crawl-delay: 2` | CKAN 3 | 388組織。九州中心だが全国の市町村が参加。組織の `name` が全国地方公共団体コード6桁なので県コードを引ける |
| 東京都オープンデータカタログ | `https://catalog.data.metro.tokyo.lg.jp` | robots.txt が 403（CloudFront既定・全UAで取得不可）→ RFC 9309 に従い制限なしとして扱う | CKAN 3 | 都本庁・水道局・消防庁・特別区・多摩市部が同居。CSV実体は各区市の自ドメインに置かれている（robots.txtはそのホストごとに確認している） |

### 2.2 robots.txt で使えないポータル（`BLOCKED_PORTALS` に記録済み）

| ポータル | 理由 |
|---|---|
| DATA-SMART CITY SAPPORO `ckan.pf-sapporo.jp` | `robots.txt: Disallow: /api/`（`Crawl-Delay: 10`）。緊急貯水槽42件・緊急時給水管路がある |
| 横浜市オープンデータポータル `data.city.yokohama.lg.jp` | `robots.txt: Disallow: /api/`。今回のキーワードでのタイトル一致は0件だった |

→ SPEC 2章 C4 / 10章に従い**クロールしない**。許諾が取れれば `PORTALS` に移すだけで有効化できる。

### 2.3 CKAN APIが無い/到達できなかったポータル（今回は対象外）

`opendata.pref.shizuoka.jp`（404）、`opendata.pref.ishikawa.lg.jp`（接続タイムアウト）、`data.city.kobe.lg.jp`（404）、
`opendata.city.chiba.jp`・`opendata.pref.saitama.lg.jp`（HTMLのみ）、`data.go.jp`・`opendata.pref.aichi.jp`・
`opendata.pref.mie.lg.jp`・`opendata.pref.gunma.jp`・`opendata.pref.tochigi.lg.jp`・`opendata.pref.kumamoto.jp`・
`open-data.pref.hyogo.lg.jp`・`data.pref.kyoto.lg.jp`・`opendata.pref.niigata.lg.jp`・`opendata.pref.toyama.jp`（DNS/接続不可）。
※ 大阪府・名古屋市・京都府・熊本県などは **BODIK に相乗りしている**ので、独自ポータルが無くても取得できている。

## 3. 検索クエリの設計（重要）

CKAN(Solr) の日本語全文検索は形態素解析で無関係なデータセットまで拾う。実測（BODIK, 2026-08-31）:

| クエリ | ヒット数 |
|---|---|
| `q=災害時給水`（全文） | 1,375 |
| `q=防災備蓄`（全文） | 705 |
| `q=給水施設`（全文） | 2,356 |
| `q=title:消防水利` | 72 |
| `q=title:応急給水` | 3 |

全文検索は 13クエリで **約60リクエスト**（100件ページング）を要して分類後87件、
`title:` 検索は **13リクエスト**で同じ87件（差は彦根市「災害備蓄品一覧」1件のみ。これは `災害備蓄` をクエリに追加して回収）。
→ **`title:<キーワード>` 検索を採用**。カタログへの負荷が1/5になる。

`SEARCH_QUERIES`: 消防水利 / 消火栓 / 防火水槽 / 給水拠点 / 応急給水 / 災害時給水 / 給水ステーション /
耐震性貯水槽 / 飲料水兼用貯水槽 / 緊急貯水槽 / 備蓄倉庫 / 防災倉庫 / 備蓄物資 / 防災備蓄 / 災害備蓄

## 4. 種別の判定と、あえて採らなかったもの

`classify()` はデータセットのタイトルだけで判定する（本文やタグは自治体ごとに書式がバラバラで信用できない）。

- `stock` … 備蓄倉庫 / 防災倉庫 / 備蓄物資 / 防災備蓄 / 備蓄品 / 備蓄食料
- `water` … 給水拠点 / 応急給水 / 災害時給水 / 給水ステーション / 耐震性貯水槽 / 飲料水兼用貯水槽 / 緊急貯水槽 / 災害用井戸
- `fire_water` … 消防水利 / 消火栓 / 防火水槽

除外キーワード（`TITLE_EXCLUDE`）で統計表・名簿を落とす: 事業者 / 業者 / 名簿 / 工事店 / 統計 / 年鑑 / 統計書 / 推移 /
普及 / 料金 / 人口 / 件数 / 面積 / レポート / 指針 / カルテ / の数 / 状況 / 計画 / 収支 / 実績 / 使用量 / 有収 / 供給水量 / 整備率 / 充足率。

**あえて採らなかったもの（判断の記録）**

| 対象 | 判断 |
|---|---|
| 「給水スポット一覧」（福岡市ほか） | マイボトル用の**平常時の給水スポット**であり災害時給水拠点ではない。混同すると危険なので除外 |
| 「給水施設」（鹿児島市、配水池等） | 水道施設台帳であり応急給水拠点とは限らない。`water` に混ぜると誤解を招くので除外 |
| 「貯水槽一覧」（墨田区）ほか修飾語なしの貯水槽 | 防火水槽なのか耐震性貯水槽（飲料水）なのか判別できない。`耐震性`/`飲料水兼用`/`緊急` が付くものだけ採用 |
| 「〜(施設カルテ)」（調布市の防災倉庫3件） | 1施設1ファイルの施設カルテXLSXで一覧ではない |

## 5. ライセンス判定（SPEC 2章 C5 / 3.3）

`license_status()` は `license_id` + `license_title` の文字列で判定する。

- **先に否定判定**: `non-commercial` / `-nc` / `no-deriv` / `-nd` / 「禁止」「不可」→ 不採用。
  `cc-by-nc` は `cc-by` を含むので、順序を逆にすると事故る（テスト `test_license_nc_beats_by` で固定）。
- **採用**: `cc-by`系 / `cc0`・`cc-zero`・public domain / `PDL 1.0` / 政府標準利用規約・公共データ利用規約 / `odc-by`
- **不採用**: `other-copyright`、`notspecified`、`gfdl`（継承条件が強く再配布条件を機械判定できない）、ライセンス未記載

BODIK 全体（今回のキーワードで拾った5,170件）のライセンス分布は
`cc-by-40-intl` 3,981 / `cc-by` 838 / `PDL1.0` 104 / `CC-BY-4.0` 100 / `cc-by-21-jp` 71 / `cc-by-21` 46 /
`other-copyright` 12 / `Truecc-by-40-intl` 5（登録側の打ち間違い。`cc-by` として採用される）/ `gfdl` 4 /
`cc-zero` 3 / `odc-by` 3 / `notspecified` 2 / `cc-nc` 1。
→ **実質すべて CC BY**。今回の採用対象でライセンス起因の不採用は0件だった（除外理由はすべて「CSVリソースなし」）。

出典は `data/facilities/index.json` の `sources[]`（自治体名・データセットタイトル・データセットページURL・ライセンス・更新日時）と、
県別ファイルの `sources[]` に必ず残る。レコードの `s` はその配列の添字。

## 6. 正規化の実装メモ（自治体CSVの現実）

- **文字コードは UTF-8(BOM付) と CP932 が半々**。`decode_csv()` が `utf-8-sig` → `cp932` → `utf-8` の順に試す。
- **列名の表記ゆれ**は NFKC 正規化＋空白除去で吸収（`所在地＿連結標記` → `所在地_連結標記`、`建物名等（方書）` → `建物名等(方書)`、`Ｎｏ` → `No`）。
  「連結**表**記」と「連結**標**記」の両方が実在するので両方を候補に入れている。
- **緯度経度の列名**は `緯度` 固定ではない: `世界緯度10進`（船橋市）、`緯度（１０進法表記）`（高島市）、
  `緯度(栓)(座標)`（彦根市）、`緯度（世界測地系WGS84 10進数）`（豊田市）。→ 完全一致 → 「緯度を含む列」の順で拾い、
  `度分秒`/`日本測地系`/`旧`/`X座標`/`Y座標` を含む列は除外。
- **緯度と経度が入れ替わっている自治体がある**ため、値のレンジで判定して入れ替える（`parse_coord`）。
- **名称列が無いCSVが多い**（消火栓は名前が無いのが普通）。その場合は `種別` 列（消火栓/防火水槽/プール/河川など）を名称に使う。
- **住所列が無いCSVも多い**。標準様式の `所在地_都道府県` + `所在地_市区町村` + `所在地_町字` + `所在地_番地以下` を連結して復元する。
- **同一データセットに年度違いのCSVが複数ぶら下がっている**（福知山市4本、箕面市3本、高島市3本、寝屋川市4本、上天草市3本など）。
  どれが最新か機械判定できないので**全部読んで座標＋名称＋種別で重複排除**している（`split_by_pref`）。

## 7. 住所しかないデータの座標補完

原データに座標が無い行は国土地理院 AddressSearch (`https://msearch.gsi.go.jp/address-search/AddressSearch`) で補完する。
既存の `crawler.geocode.Geocoder` をそのまま使う（1req/s・市区町村より粗い結果は棄却するロジック込み）。
キャッシュだけ `data/facilities_geocache.json` に分けてコミットし、月次実行で再問い合わせしないようにしている。

- 補完したレコードには **`g: 1`** を立てる。アプリ側で「おおよその位置」として区別できる（SPEC 11章のリスク対策）。
- 亀山市のように**所在地が町丁目までしか無い**自治体では、同一町丁目の消火栓が全部同じ座標に積み上がる。
  そのため `split_by_pref` で (県, 種別, 緯度, 経度, 名称) が同じレコードを1件にまとめている。
- 1回の実行で新規に問い合わせる住所は既定 **2000件**まで（`--geocode-limit` / workflow の入力で変更可）。
  キャッシュ済みの住所は上限を消費しないので、**月次実行を重ねるほど補完率が上がる**設計。
- 今回は3回に分けて計 **8,210件** の住所をキャッシュに貯め、座標なし15,809件のうち15,587件（98.6%）を補完できた。
  キャッシュを含む状態なら1回の実行は約10分で終わる。初回だけ既定2000件では足りないので
  `--geocode-limit` を大きくするか、月次実行を数回まわして収束させる。

## 8. 運用

- `.github/workflows/facilities.yml` … 毎月1日 JST 04:00（`0 19 1 * *`）＋ `workflow_dispatch`。
  差分があれば `livecam-jp-bot` でコミットし、`publish.yml` を明示起動する（`shelters.yml` と同じ手順）。
  `data/facilities/`・`data/facilities_state.json`・`data/facilities_geocache.json` をコミット対象にしている。
- `publish.yml` の trigger paths に `data/facilities/**` を追加済み。
- `site/build.py` が `tools.facilities.sync_site()` を呼んで `data/facilities/` → `site/v1/facilities/` にコピーする。
  **publish環境には requests が無い**ので `tools/facilities.py` のトップレベルは標準ライブラリのみ、
  `requests`/`truststore`/`crawler.geocode` はすべて遅延importにしてある。
- 台帳の公開は全ユーザーに再取得を発生させるため、月1回にまとめている（CLAUDE.md「定期実行の知見」）。

## 9. 今後の拡張手順

1. **ポータルを増やす** … `PORTALS` に `{"key","name","base","delay","default_pref"/"org_name_is_jis"}` を1行足すだけ。
   追加前に必ず `curl https://<host>/robots.txt` で `/api/` が許可されているか確認する。拒否なら `BLOCKED_PORTALS` へ。
2. **キーワードを増やす** … `SEARCH_QUERIES` に足し、対応する種別を `KIND_TITLE_KEYWORDS` に足す。
   タイトル判定を変えたら `tools/tests/test_facilities.py::test_classify_*` にケースを足すこと。
3. **XLSX に対応する** … 現状の不採用17件のうち**13件がXLSX/XLS**（東京消防庁の消火栓及び防火水槽等、福岡市消防水利施設一覧、
   豊田市の消火栓・防火水槽一覧など、量の多い自治体が含まれる）。`openpyxl` を requirements に足して
   `decode_csv` の隣に `read_xlsx()` を作れば一気に増える。**次にやるならこれが一番費用対効果が高い**。
4. **HTMLリソースに対応する** … 清瀬市・日野市はリソース形式が HTML（自治体サイトの表ページ）。個別パーサが要るので優先度は低い。
5. **札幌市・横浜市** … robots.txt の許諾を得られたら `PORTALS` へ移すだけ。
6. **カバーされていない県** … 下表参照。BODIKに参加していない自治体は独自ポータル or PDF/HTML公開が多い。
   都道府県単位で「消防水利施設一覧 オープンデータ」を当たり、CKANがあればポータルを足すのが最短。
