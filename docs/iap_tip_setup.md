# 開発者支援（アプリ内課金）のセットアップ手順

「設定 → 開発者を応援する」の投げ銭4段階（消耗型）。実装は `app/lib/ui/tip_screen.dart`。

## 商品ID（アプリ側の定義と一致させる）
| 参照名 | 商品ID | 種別 |
|---|---|---|
| Tip Coffee | `jp.livecam.tip.coffee` | 消耗型 |
| Tip Sweets | `jp.livecam.tip.sweets` | 消耗型 |
| Tip Lunch | `jp.livecam.tip.lunch` | 消耗型 |
| Tip Dev Tools | `jp.livecam.tip.devtools` | 消耗型 |

## 「支援メニューは準備中です」と出るとき
`InAppPurchase.isAvailable()` は true だが `queryProductDetails` が空、という状態。原因は次の順で疑う。

1. **有料App契約（Paid Applications Agreement）が未締結・未更新**。App Store Connect →「ビジネス」。これが有効でないと商品は絶対に返らない
2. **課金アイテムが「下書き」または「メタデータが不足」**。この状態の商品は Sandbox / TestFlight でも返らない。
   「送信準備完了」にするには 価格・ローカリゼーション（表示名・説明）・**審査用スクリーンショット**・審査メモ が要る
3. 商品IDの綴り違い、バンドルIDの不一致

## 審査用スクリーンショットの堂々巡りを抜ける
商品が返らないと支援メニューが描画されず、描画できないとスクリーンショットが撮れない。
**Xcode の StoreKit 構成ファイル**（`app/ios/Tips.storekit`）を使うとローカルの疑似ストアで商品が返るので、
App Store Connect の状態に関係なく実際の価格つきで画面を出せる。

1. Xcode で `app/ios/Runner.xcworkspace` を開く
2. Product → Scheme → Edit Scheme → Run → Options → **StoreKit Configuration** に `Tips.storekit` を選ぶ
3. シミュレータで実行 → 設定タブ → 「開発者を応援する」→ 4段階が価格つきで並ぶ
4. `Cmd+S`（シミュレータのFile → Save Screen）で撮影
5. **撮り終えたら Scheme の StoreKit Configuration を None に戻す**（本番ビルドに影響はないが、実ストアの検証ができなくなる）

`Tips.storekit` の価格は表示確認用。App Store Connect 側の実価格に合わせて編集してよい。

## スクリーンショットの要件
- 課金アイテム1件ごとに「審査に関する情報」へ登録する（4件とも同じ画像でよい）
- 最小 640×920 ピクセル。iPhoneのスクリーンショットならそのまま通る
- 審査担当者への参考資料であり、ユーザーには表示されない
- その課金で何が得られるか分かる画面であること。この投げ銭は特典が無いので、4段階と価格が並んだ支援画面がそれに当たる

## 提出
初回は課金アイテムをアプリのバージョンと一緒に審査へ出す。App Store Connect のバージョンページ
「アプリ内購入」セクションで4件を選択してから提出する（別々に出すと審査されない）。

## 支援へのお礼としての広告非表示（1.5.1・2026-09-20）

- 広告非表示を「販売」するのではなく、支援へのお礼として一定期間広告を出さない（アプリ内だけで完結。ストア側の設定変更は不要）
- お礼の期間: Coffee 1か月（30日）／ Sweets 3か月（90日）／ Lunch 8か月（240日）／ Dev Tools 24か月（730日）。期間中の再支援は残りに加算
- 期限は端末内に保存（消耗型は復元不可のため、再インストール・機種変更では引き継がれない旨を画面に明記）
- 商品説明を更新する場合の例（任意）: 「開発者への応援です。お礼として○か月間、アプリ内の広告を表示しません（端末内で管理。再インストール時は引き継がれません）」
